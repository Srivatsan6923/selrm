## Section 3.1, "Edits and invariants"

**3.1-12.** "The engine edits the mentions of one input of a criterion c_j and keeps an edit only if
executing the program confirms its invariant." *Matches.* `engine.check` runs on every proposal,
and a failing proposal is drawn again (`make_group`).

**3.1-13.** "A flip changes a mention that A_j counts so that c_j changes, no other criterion does,
and the target claim changes; the engine checks the claim itself."
- *Matches.* `check` executes every claim type (conclusion, and the criterion claim for constraint
  rules) and requires that exactly the target criterion changes.
- **Add:** the other criteria are set so that the target decides the conclusion (`engine.pivots`).
  That is why no proposal is ever rejected for an indecisive flip (item C-2).

**3.1-14.** "A near-miss ... is numeric (a counted value moves toward the threshold without
crossing; a value exactly at the threshold is reported as its own kind)."
- *Partly.* The numeric near-miss value lies strictly within one near-miss window of the threshold,
  on the default side, and closer to it than the base value.
- The kind "boundary" is a value exactly at a **strict** threshold ("above 30", value 30).
- At an inclusive threshold, a value at the threshold meets the criterion, so it is used as a flip
  (one third of flips at inclusive thresholds), never as a near-miss.
- Proposed wording: *"a value exactly at a strict threshold is its own kind; at an inclusive
  threshold the same value is a flip"*.

**3.1-15.** "or concerns applicability (the concept and value of the flip are reported in a
mention that A_j does not count: another subject, absent status, or a time outside A_j)."
- *Partly.*
- **Findings:**
  - subject: a person the predicate does not count, at the flip's time (current or past);
  - negation: a named denial for the patient;
  - time: a past or resolved mention, or a delabelled allergy.
- **Measurements:**
  - the time near-miss keeps the current value on the default side and moves an older, dated value
    across the threshold;
  - measurements have no subject or negation near-misses.
- A negation near-miss names the concept with status absent, so it does not report "the value of
  the flip". Say "the concept of the flip".

**3.1-16.** "A presentation edit re-renders the same state with another unit, order or template,
matched in size to the flips."
- *Does not match.*
- No unit ever changes: each input has one unit.
- What a presentation edit changes:
  - always a new line order;
  - another header frame;
  - other templates for numeric current values and dated past values (same value and year).
- Findings, superseded values and filler lines keep their wording. A finding template states
  specific facts, and the round-1 reviewers found that re-templating findings changed facts.
- The edit is not matched in size to a flip. It reorders every line, while a flip replaces one.
- Proposed wording: *"re-renders the same state in another line order and header, with measured
  values reworded; one presentation case per group"*.

**3.1-17.** "For missing twins we distinguish explicit absence, which determines a criterion, from
an unknown input." *Matches.*
- For a finding, the twin replaces the base line with an "unknown" line ("unknown", "not
  obtained", "status unclear"; status unknown).
- For a measurement, the line is dropped.

**3.1-18.** "With C_ρ(z') the non-empty set of admissible completions ... supported / refuted /
undetermined; inconsistent states are excluded."
- *Partly.* The code does not enumerate every admissible completion.
- `_check_missing` executes the program on two completions of the decisive input, the base mention
  and the flip mention. It keeps the twin only if these reach both outcomes for every claim type,
  which is sufficient for "undetermined".

**3.1-19.** "A missing twin is kept only if the target claim is undetermined." *Matches.* The target
is decisive by construction, and `_check_missing` verifies it. Regenerated from the frozen seeds,
the missing set had 0 rejected of
1,000 proposals.

**3.1-20.** "A verdict '+' means supported; '-' covers refuted and undetermined claims." *Outside
the generator.* Missing-twin records label both claims 0.

**3.1-21.** "How omitted information is read is a stipulated convention ... (measurements unknown,
history items absent unless the case says otherwise)." *Matches.*
- `Criterion.evaluate`: an unmentioned finding is absent.
- `engine.ledger`: an unmentioned measurement is "unknown" and an unmentioned finding "absent".
- A measurement criterion cannot execute without its value, so every labelled case states it.
